# 涂地大作战

一个跑在浏览器里的 3D 涂地对战小游戏。地图是江南大学蠡湖校区的简化版——有河、有桥、有楼，走桥才能过河。
90 秒内把自己颜色的面积涂得比对手多就赢。

- 纯前端，不需要构建，不需要装依赖
- 所有贴图都是 Canvas 运行时画出来的，没有一张图片文件
- 支持单人练习和两人联机

## 直接玩

联机有两种跑法，代码会自动选：

| 部署方式 | 联机怎么走 |
| --- | --- |
| GitHub Pages / 任意静态托管 | WebRTC 点对点直连，房主的浏览器自己当服务器 |
| 本地 `node server.js` | WebSocket，走局域网服务器 |

页面加载后会请求一次 `./health`：自己的服务器会返回 `{"ws":true}`，静态托管会 404，
于是自动切到 P2P。对 `game.js` 来说两种传输的接口完全一样。

## 本地运行

```bash
node server.js
# 打开 http://127.0.0.1:8848/
```

Windows 上直接双击 `启动游戏.bat` 也行。没装 Node 时脚本会退回 Python 静态服务器，
但那样只能单机（WebSocket 起不来）。

同一个 WiFi 下的手机/另一台电脑，用启动时打印的那个局域网地址访问即可。

## 联机流程

1. 房主点「创建房间」，拿到一个 4 位房间号（去掉了 O/0/I/1/B/8 这些容易看错的字符）
2. 另一台设备打开同一网址，输入房间号，点「进入」
3. 双方倒数 3 秒后同时开跑，90 秒后出结算，点「再来一局」会同时给双方重开

## 操作

- 电脑：`WASD` / 方向键移动
- 手机：左下角虚拟摇杆

## 规则

- 走过的地方留下自己的颜色，后来的颜色覆盖先前的
- 把自己的颜色连成一个**封闭图形**，内部会被整片填满（围地）
- 河面不能涂，得走桥
- 时间到，面积占比高的一方获胜

## 代码结构

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面骨架、HUD、大厅、样式 |
| `game.js` | 主循环、角色、输入、渲染、联机客户端 |
| `net.js` | 网络层：`ws` 和 `p2p` 两种传输，接口一致 |
| `server.js` | 零依赖的静态服务 + WebSocket 房间服务（局域网用） |
| `world.js` | 场景搭建：地面、水面、桥、建筑、树、路灯、遮挡淡出 |
| `map.js` | 地图数据：地形、障碍、步道、树和路灯的生成规则 |
| `territory.js` | 涂色格子的归属统计、封闭区域填充 |
| `textures.js` | 全部程序化贴图（草地、石板、木纹、石材、立面、水法线…） |
| `lib/` | three.js r160 与 PeerJS 的本地副本 |

## 实现上的几个取舍

**不用 `ws` 包。** WebSocket 握手和帧编解码是 RFC 6455 里写死的东西，自己实现一百多行就够，
换来的是"解压双击就能跑、不装依赖"。

**服务器不做游戏逻辑。** 只负责房间、转发和权威计时。双方各自跑同一套 `territory.js`，
涂色同步的是**笔迹** `[x, z, r]` 而不是"哪一格变了"——笔迹天然带先后顺序，
"后涂的盖住先涂的"这条规则在网络同步时才能成立。

**P2P 模式下房主兼任服务器。** 开局、计时、转发都在房主那一端，客人直连过去。
因为协议和 WebSocket 版逐字相同，客户端逻辑不用分叉。

**断线检测靠心跳。** WebRTC 在对端进程被直接杀掉时不会主动报 `close`（实测 45 秒都没有），
所以两边每 2 秒互发一次 `ping`，18 秒没有任何消息就判定对方离开。

**计时不用累加 dt。** 低帧率设备上如果按帧累加，90 秒的局会被拖成 150 秒。
开局倒数按墙钟算剩余，物理步长和计时步长分开截断。

## 已知限制

- P2P 只配了公共 STUN，没有 TURN。少数对称 NAT 网络（部分手机热点、公司网络）会连不上，
  这时候换回局域网 `node server.js` 的方式即可。
- 房间号是 4 位、全服共享的公共信令命名空间，极小概率撞号，撞了会自动换一个。
